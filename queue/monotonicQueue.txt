# MONOTONIC QUEUE

1. DEFINITION

---

A Monotonic Queue is a queue-like data structure that maintains
elements in either increasing or decreasing order.

It is usually implemented using a DEQUE (Double-Ended Queue).

Monotonic Queue = pattern / behavior
Deque = underlying data structure

2. WHY DEQUE INSTEAD OF QUEUE?

---

Normal Queue:

```
Insert  -> Back
Remove  -> Front
```

Monotonic Queue needs:

```
Insert       -> Back
Remove       -> Front
Remove       -> Back
```

Therefore, we use a Deque.

Deque supports operations from both ends.

3. TYPES

---

A. MONOTONIC DECREASING QUEUE

Elements are maintained from largest to smallest.

```
Front              Back
  |                  |
  v                  v
[9, 7, 5, 2]
```

The largest element is always at the FRONT.

Used for:

```
Sliding Window Maximum
```

When inserting x:

```
while back < x:
    remove back
```

B. MONOTONIC INCREASING QUEUE

Elements are maintained from smallest to largest.

```
Front              Back
  |                  |
  v                  v
[2, 5, 7, 9]
```

The smallest element is always at the FRONT.

Used for:

```
Sliding Window Minimum
```

When inserting x:

```
while back > x:
    remove back
```

## 4. CORE IDEA

The key idea is:

```
REMOVE USELESS / DOMINATED ELEMENTS
```

Example for finding maximum:

```
Current deque:

[7, 5, 3]

New value:

9
```

Since 9 is:

```
- larger
- newer
```

the old values 7, 5 and 3 can never become the maximum
while 9 remains inside the window.

Therefore:

```
[7, 5, 3]
      |
      | new 9
      v

[9]
```

This is called the DOMINATION idea.

5. SLIDING WINDOW MAXIMUM

---

Example:

```
nums = [1, 3, -1, -3, 5, 3, 6, 7]
k = 3
```

Windows:

```
[1, 3, -1] -> 3
[3, -1, -3] -> 3
[-1, -3, 5] -> 5
[-3, 5, 3] -> 5
[5, 3, 6] -> 6
[3, 6, 7] -> 7
```

Answer:

```
[3, 3, 5, 5, 6, 7]
```

Use a DECREASING MONOTONIC DEQUE.

6. WHY STORE INDICES?

---

We normally store INDICES instead of values.

Example:

```
index:  0  1   2   3  4
value:  1  3  -1  -3  5
```

Deque:

```
[1, 2, 3]
```

means:

```
nums[1] = 3
nums[2] = -1
nums[3] = -3
```

Why?

Because we need to know when an element leaves
the sliding window.

If:

```
i = current index
k = window size
```

An index is expired when:

```
index <= i-k
```

Then remove it from the FRONT.

7. TWO DIFFERENT REMOVAL OPERATIONS

---

A. REMOVE FROM BACK

Purpose:

```
Maintain monotonic order.
```

For maximum:

```
while nums[back] <= nums[i]:
    remove back
```

B. REMOVE FROM FRONT

Purpose:

```
Remove an element that has expired from the window.

if deque.front <= i-k:
    remove front
```

Remember:

```
Back removal
-> maintains monotonic property

Front removal
-> maintains window boundaries
```

## 8. ALGORITHM FOR SLIDING WINDOW MAXIMUM

For every element:

STEP 1:
Remove expired indices from the FRONT.

```
if deque.front <= i-k:
    remove front
```

STEP 2:
Remove smaller elements from the BACK.

```
while back value <= current value:
    remove back
```

STEP 3:
Add the current index to the BACK.

STEP 4:
Once the first window is complete:

```
answer = nums[deque.front]
```

## 9. GO IMPLEMENTATION

func maxSlidingWindow(nums []int, k int) []int {
deque := []int{}
result := []int{}

```
for i := 0; i < len(nums); i++ {

    if len(deque) > 0 && deque[0] <= i-k {
        deque = deque[1:]
    }

    for len(deque) > 0 && nums[deque[len(deque)-1]] <= nums[i] {
        deque = deque[:len(deque)-1]
    }

    deque = append(deque, i)

    if i >= k-1 {
        result = append(result, nums[deque[0]])
    }
}

return result
```

}

10. WHY IS IT O(N)?

---

The code contains a for loop and a while loop,
but the total complexity is still O(n).

Reason:

Every element can:

```
Enter the deque -> at most once
Leave the deque -> at most once
```

Therefore:

```
Maximum insertions = n
Maximum removals  = n
```

Total:

```
O(n)
```

Space:

```
O(k)
```

## 12. MAXIMUM VS MINIMUM

For MAXIMUM:

```
Use decreasing deque.

[9, 7, 5, 2]

Largest element is at FRONT.
```

For MINIMUM:

```
Use increasing deque.

[2, 5, 7, 9]

Smallest element is at FRONT.
```

Memory rule:

```
MAX -> DECREASING -> largest at front

MIN -> INCREASING -> smallest at front
```

## 13. IMPORTANT INTERVIEW QUESTION

Question:

```
Why do you remove elements from the back?
```

Answer:

```
We remove elements that are dominated by the new element.

For a maximum query, if the new element is larger
and appears later, an older smaller element can
never become the maximum while the new element
remains inside the window.

Therefore, the older smaller element is useless
and can be removed.
```

## 14. MENTAL MODEL

For a maximum:

```
              NEW VALUE
                  |
                  v
        Remove smaller elements
             from BACK
                  |
                  v
             Add new index
                  |
                  v
          +-------------+
          |    DEQUE    |
          |             |
          | MAX <- FRONT|
          |             |
          |             |
          |      BACK <-|
          +-------------+
                  |
                  v
         Remove expired
          indices from
              FRONT
```

9. ONE-LINE DEFINITION

---

A Monotonic Queue is a deque-based technique that keeps
only useful candidates in sorted order, allowing
sliding-window minimum/maximum queries in O(n).

17. MOST IMPORTANT THINGS TO REMEMBER

---

1. Monotonic Queue is a PATTERN, not a separate basic
   data structure.

2. It is usually implemented using a DEQUE.

3. Maximum -> decreasing deque.

4. Minimum -> increasing deque.

5. Store INDICES, not just values, when working with
   sliding windows.

6. Remove from BACK to maintain monotonic order.

7. Remove from FRONT when an index leaves the window.

8. Each element enters and leaves at most once.

9. Therefore total time complexity is O(n).

10. The core idea is DOMINATION:
    remove candidates that can never become the answer.
